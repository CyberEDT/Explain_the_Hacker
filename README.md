# Explain The Hacker — CyberEDT

> **Simulate, visualize, and understand real-world attack chains.**
> A powerful, browser-based threat simulation engine that maps exposed infrastructure, misconfigurations, and raw log data directly to a deterministic 7-stage Cyber Kill Chain, generating highly accurate threat narratives and Indicators of Compromise (IOCs).

---

## 🔥 Key Features

- 🎯 **Advanced v4 Threat Correlation Engine** — Dynamically correlates user inputs to generate hyper-realistic threat vectors mapping directly to the 7 stages of the Cyber Kill Chain (Reconnaissance to Actions on Objectives).
- 🧠 **Adaptive Intelligence Levels** — Tailors the analytical output based on the target audience (`LOW`, `MEDIUM`, `HIGH`, `LE`). Automatically simplifies narratives, hides complex matrices, and translates technical jargon for beginners, while unleashing deep MITRE mappings and forensic correlations for experts.
- 📊 **Dynamic MITRE ATT&CK Mapping** — Extracts and groups techniques (e.g., T1595, T1078) by tactic, mapping them to observed, inferred, or hypothetical evidence with strict confidence boundaries.
- 🔐 **Privacy-First Persistent History** — Automatically saves your recent threat analyses natively to the browser's 5MB `localStorage` utilizing an AES/XOR cipher. Operates strictly under user consent via a global privacy banner.
- 🔍 **Robust Input Parsing** — Supports up to 50 ports and 20 misconfigurations with regex-powered categorization for cloud leaks, credential stuffing, and unpatched infrastructure.
- 🛡️ **Intelligent Mitigations** — Provides prioritized, emergency defense recommendations sorted by severity and dynamically capped to prevent overwhelming non-technical users.
- 📈 **Sleek Data Visualization** — Recharts-powered Risk Gauges, interactive Kill Chain flows, and dynamic Evidence Badges.
- 🚀 **SEO & Performance Optimized** — Fully equipped with Canonical URLs, Open Graph Meta tags, Twitter Cards, and Strict Content-Security-Policies tailored for `www.cyberedt.com`.

## ⚙️ Core Engine Mechanics (v4)

### 1. Deterministic 7-Stage Cyber Kill Chain
The ETH engine maps all threats against a strict 7-stage sequential framework. If a phase lacks telemetry, it defaults to `NOT OBSERVED` rather than fabricating data.
- **01 Reconnaissance:** Port scanning, service enumeration, and OSINT gathering.
- **02 Weaponization:** Exploits bundled with payloads tailored to discovered misconfigurations.
- **03 Delivery:** How the malicious payload reaches the target (e.g., direct port interaction, brute force).
- **04 Exploitation:** Triggering the vulnerability (e.g., CVE-exploitation, auth bypass).
- **05 Installation:** Establishing a beachhead (e.g., web shells, backdoors).
- **06 Command & Control:** Outbound communications to threat actor infrastructure.
- **07 Actions on Objectives:** Ransomware execution, data exfiltration, or database dumping.

### 2. Strict Confidence Scoring
Every MITRE technique generated by the engine is assigned a strict confidence score to prevent AI hallucinations:
- **Verified Evidence (90-100%):** Direct match from user telemetry (e.g., "Port 3389 Open").
- **Strong Inference (70-89%):** Highly likely given the environment (e.g., brute forcing an open SSH port).
- **Moderate Inference (50-69%):** Plausible tactic based on related misconfigurations.
- **Weak Inference (30-49%):** Possible, but lacking direct evidence.
- **Hypothetical Scenario (20-29%):** Predictive modeling of what an attacker *might* do.

### 3. Adaptive Intelligence Levels
The engine dynamically alters the UI, narrative, and depth of analysis based on the selected target audience:
- **LOW (Executives/Beginners):** Focuses on plain-English summaries. Hides complex MITRE matrices, suppresses T-IDs, truncates mitigations, and explains unobserved kill chain stages theoretically.
- **MEDIUM (IT/Sysadmins):** Balances technical detail with operational guidance. Introduces the MITRE ATT&CK matrix and standard mitigations.
- **HIGH (SOC Analysts):** Unlocks the full analytical matrix, displaying deep threat correlations, exact MITRE T-IDs, and advanced forensic theories.
- **LE (Law Enforcement/DFIR):** Optimizes the narrative for chain-of-custody, focusing heavily on evidentiary weight, objective findings, and criminal abuse potential.

## ⚙️ Environment Variables

Copy `.env.example` to `.env` and configure:

```bash
cp .env.example .env
```

| Variable | Default | Description |
|----------|---------|-------------|
| `VITE_USE_MOCK` | `true` | Set to `false` to use the real live CyberEDT API endpoint. |
| `VITE_API_BASE_URL` | `https://api.cyberedt.com/v1` | Backend API base URL. |

> **Security Note**: Never commit your real `.env.production` files.

## 🔒 Security Posture

- **Client-Side Obfuscation**: All persistent simulation history stored in `localStorage` is completely obfuscated using a Base64 XOR cipher to prevent plain-text exposure in browser Developer Tools.
- **XSS Prevention**: Every single text node generated by the engine is rigorously sanitized via custom string replacement before being mounted to the DOM. Zero usage of `dangerouslySetInnerHTML`.
- **Strict CSP**: A tight Content-Security-Policy restricts external script execution and strictly defines `api.cyberedt.com` as the only trusted data source.
- **Privacy Consent**: Full GDPR/CCPA compliance regarding local browser storage via an explicit, un-intrusive consent banner.
